# 開發專案計畫

- 文件版本：1.1
- 更新日期：2026-03-14
- 開發階段：實驗性開發 / 小規模遊戲階段
- 產品定位：以遊戲為主、程式教育為核心玩法之一
- 目標平台：電腦單機

## 1. 專案目標

本專案要驗證一個 2D 劇情闖關遊戲是否能把程式挑戰自然嵌入主流程。  
玩家會在節點式主地圖上推進，觸發劇情後進入編程頁面，用積木與 Python 完成關卡，並以此解鎖下一個節點。

本階段主要驗證：

- 劇情、地圖節點與程式關卡能否形成自然流程
- 關卡介紹頁與支線練習關是否能形成有效的學習節奏
- 工具包、積木解鎖與電池能量規則是否能成立
- 現有 Block2Python 核心是否能延續到遊戲系統中

## 2. 核心背景

- 作品暫定名稱：《Code Planet：拯救程式星球》
- 舞台：Code Planet（程式星球）
- 問題：Bug King 破壞系統，使各城市程式失控
- 主角：玩家 + AI 機器人 Byte
- 目標：修復各城市系統，逐步恢復程式星球能量

## 2.1 名稱分層原則

- `Block2Python`：目前作為技術核心 / repository 名稱使用
- 《Code Planet：拯救程式星球》：目前作為遊戲產品暫定名稱使用
- 後續文件若描述遊戲內容、玩家體驗與劇情，應優先使用遊戲產品名稱
- 後續文件若描述既有 Python repo、挑戰核心、Blockly / Judge / Analysis 能力，應優先使用 `Block2Python`
- 在尚未拆出獨立遊戲專案前，允許同一 repository 同時承載遊戲規劃與技術核心，但文件中不得混淆兩者角色

## 3. 核心玩法

### 3.1 主流程

1. 進入節點式主地圖
2. 選擇或推進目前可進入節點
3. 觸發對話、任務或劇情事件
4. 若節點包含程式內容，切換到編輯頁
5. 完成關卡介紹頁或支線練習關
6. 回寫結果並解鎖下一個節點

### 3.2 關卡結構

- 主線：負責推進故事
- 關卡介紹頁：展示新解鎖積木，透過工作區積木一鍵轉 Python 建立積木與 Python 對應理解
- 支線練習關：固定 5 題，以 Python 作答為主
- 工具包：卡關時可用積木輔助，但不能直接用來通關

### 3.3 關鍵規則

- 工具包只要在單題內開啟過一次，該題獎勵固定為 10%
- 未使用工具包時，單題獎勵為 20%
- 每組支線練習關固定 5 題
- 電池能量超過 80% 才能過關，實際只接受 90% 或 100%
- 若失敗，需等待 3 分鐘後重跑整組支線練習關

## 4. 本階段交付目標

- 一張可操作的節點式主地圖
- 一段可玩的主線流程
- 至少一組關卡介紹頁
- 至少一組固定 5 題的支線練習關
- 工具包、積木解鎖與電池能量規則可運作
- 程式關卡結果可回寫並解鎖下一個節點

## 5. 主要風險

- 劇情與程式關卡綁定過深，後續修改成本高
- 節點地圖、劇情觸發與關卡入口關係不清楚
- 現有 Blockly / PySide6 互動形式未必適合最終遊戲呈現
- 工具包與電池規則若節奏不佳，可能讓玩家只感受到阻礙

## 6. 待補項目

- 各城市設定與章節主題
- 玩家角色與主要衝突細節
- 積木與 Python 的長期解鎖節奏
- 美術風格與演出深度
- 鏡頭與地圖推進形式
- 遊戲引擎 / UI 承載方案
