# 遊戲需求文件

- 文件版本：2.2
- 更新日期：2026-03-20
- 產品定位：遊戲主體 / 程式教育核心玩法
- 開發階段：實驗性開發 / 小規模遊戲階段

## 1. 範圍

### 1.1 本階段包含

- 2D 遊戲畫面
- 節點式主地圖
- 劇情推進與對話框互動
- 進入頁與玩家角色建立
- 主線 / 支線關卡路線
- 程式編輯頁切換
- 積木與 Python 挑戰
- 工具包與積木解鎖
- 電池能量與支線練習關解鎖規則
- AI 助教
- 單機存檔

### 1.2 本階段不包含

- 多人模式
- 線上帳號與雲端同步
- 教師後台
- 最終版美術與完整劇情演出定稿

## 2. 劇情背景

- 作品暫定名稱：《Code Planet：拯救程式星球》
- Code Planet 的城市由程式能量運作
- Bug King 破壞系統後，城市程式開始失控
- 玩家與 AI 機器人 Byte 透過學習程式語言修復各城市系統

## 3. 系統流程

1. 玩家進入遊戲開場流程
2. 在進入頁建立玩家角色，選擇男 / 女並輸入名稱
3. 玩家角色建立成功後，進入節點式主地圖
4. 在地圖上選擇目前可進入節點
5. 進入該節點對應的控制浮頁
6. 由控制浮頁選擇進入劇情、示範關或支線練習關
7. 完成當前內容後可返回主地圖
8. 依序通關劇情、示範關或支線練習關
9. 回寫結果並解鎖下一個主線或支線節點

## 4. 功能需求

### FR-1 地圖與劇情

- 系統需提供節點式主地圖
- 系統需提供明確主線路線
- 系統需支援支線節點
- 系統需支援地圖節點上的劇情事件與對話框互動
- 系統需支援主地圖前後的劇情觸發點，以承接開場導入與後續故事背景交代
- 系統需支援劇情角色、旁白與其他角色共同參與對話式劇情演出

### FR-1A 開場進入流程

- 系統需提供進入頁，作為玩家首次進入遊戲的流程入口
- 系統需允許玩家在進入頁選擇男 / 女角色外觀
- 系統需允許玩家在進入頁輸入玩家名稱
- 系統需在玩家角色建立成功後才進入主地圖
- 系統需保留進入頁前後的劇情觸發空間，但具體劇情腳本與觸發時機可於後續版本再定

### FR-2 關卡進入與切換

- 系統需能從地圖節點進入控制浮頁
- 系統需能由控制浮頁進入劇情事件、示範關與支線練習關
- 系統需能在需要編程時切換到獨立編輯頁
- 系統需能在劇情、控制浮頁、主地圖與關卡頁面之間維持一致切換流程
- 系統需能將關卡結果回寫到遊戲進度

### FR-2A 控制浮頁

- 系統需提供控制浮頁，作為地圖節點與後續內容之間的統一入口
- 控制浮頁需能承接該節點可進入的劇情、示範關或支線練習關
- 控制浮頁需避免玩家在劇情結束後回到不明確的中間流程狀態
- 控制浮頁與劇情、示範關、支線練習關的進入規則，需可配合既有實作再細化

### FR-3 示範關

- 系統需支援示範關作為新積木解鎖節點
- 系統需支援玩家在示範關中以拖曳積木完成任務
- 系統需在驗證時直接顯示對應的 Python 轉換結果

### FR-4 支線練習關

- 練習關需要在示範關有進入過才能解鎖
- 系統需支援固定 5 題的支線練習關
- 題庫需固定，不採隨機抽題
- 練習關預設只能以 Python 作答

### FR-5 工具包

- 系統需提供工具包，用於存放已解鎖的 Blockly 積木
- 工具包中的可用積木需隨進度增加
- 玩家可在練習關卡住時開啟工具包改用積木輔助
- 工具包模式只能知道答案是否正確，不能直接作為通關結果
- 玩家若使用過工具包，仍需切回 Python 並以 Python 通過該題
- 工具包可在單題內不限次數開關
- 只要該題曾開啟過工具包，該題獎勵固定為 10%

### FR-6 電池能量

- 支線練習關開始時，電池能量歸零
- 未使用工具包時，單題獎勵 20%
- 使用工具包時，單題獎勵 10%
- 5 題結束後，電池能量需超過 80% 才能過關
- 超過 80% 的實作規則為只接受 90% 或 100%
- 若失敗，需等待 3 分鐘後重新挑戰整組練習關

### FR-7 驗證與評測

- 系統需驗證程式結構與輸出結果
- 系統需支援每個關卡各自的規則與測資
- 系統需區分示範關與支線練習關的驗證流程

### FR-8 進度與存檔

- 系統需保存主線、支線與程式關卡進度
- 系統需保存積木解鎖、工具包內容與劇情狀態
- 系統需保存支線練習關冷卻與完成狀態
- 系統需保存玩家角色建立結果，至少包含角色選擇與玩家名稱
- 系統需支援單機存檔

### FR-9 AI 助教

- 系統需保留 AI 助教
- AI 助教應以提示與引導為主
- AI 助教不應直接破壞 Python 練習要求

### FR-10 UI 與呈現

- 系統需以 2D 為主要方向
- 系統需支援開場進入頁
- 系統需支援節點式主地圖畫面
- 系統需支援控制浮頁
- 系統需支援角色貼圖與對話框互動
- 系統需支援獨立劇情場景
- 系統需支援開場頁、劇情場景、主地圖與編輯頁之間的切換
- 劇情場景需支援空背景、角色剪影與下方半透明對話框
- 角色剪影需支援亮起、變暗、出現與消失等演出方式
- 對話框需固定在畫面下方共用位置，並以一次一段文字的方式呈現
- 玩家點擊後需能進入下一段對話，直到該段劇情播放完成

## 5. 非功能需求

- 目標平台為電腦單機
- 畫面切換與編輯頁切換需保持基本流暢
- 程式執行需維持隔離與可控
- 冷卻與支線進度狀態需可正確保存與恢復
- 玩家角色建立資料需可正確保存與恢復

## 6. 待補資訊

- 各城市設定與章節主題
- 玩家角色與主要衝突
- 開場劇情腳本與進入頁前後的觸發時機
- 控制浮頁上的劇情、Demo、練習關進入規則與優先順序
- 劇情腳本的角色配置、旁白使用規則與實際演出節奏
- 積木與 Python 的長期解鎖節奏
- 美術風格與演出深度
- 鏡頭與地圖推進形式
- UI 承載方案
