# 遊戲需求文件

- 文件版本：2.1
- 更新日期：2026-03-14
- 產品定位：遊戲主體 / 程式教育核心玩法
- 開發階段：實驗性開發 / 小規模遊戲階段

## 1. 範圍

### 1.1 本階段包含

- 2D 遊戲畫面
- 節點式主地圖
- 劇情推進與對話框互動
- 主線 / 支線關卡路線
- 程式編輯頁切換
- 積木與 Python 挑戰
- 工具包與積木解鎖
- 電池能量與支線練習關解鎖規則
- AI 助教
- 單機存檔

### 1.2 本階段不包含

- 多人模式
- 線上帳號與雲端同步
- 教師後台
- 最終版美術與完整劇情演出定稿

## 2. 劇情背景

- 作品暫定名稱：《Code Planet：拯救程式星球》
- Code Planet 的城市由程式能量運作
- Bug King 破壞系統後，城市程式開始失控
- 玩家與 AI 機器人 Byte 透過學習程式語言修復各城市系統

## 3. 系統流程

1. 玩家進入節點式主地圖
2. 在地圖上選擇目前可進入節點
3. 節點觸發劇情、任務說明或事件
4. 若節點包含程式內容，切換到編輯頁
5. 完成示範關或支線練習關
6. 回寫結果並解鎖下一個主線或支線節點

## 4. 功能需求

### FR-1 地圖與劇情

- 系統需提供節點式主地圖
- 系統需提供明確主線路線
- 系統需支援支線節點
- 系統需支援地圖節點上的劇情事件與對話框互動

### FR-2 關卡進入與切換

- 系統需能從地圖節點進入劇情事件與程式關卡
- 系統需能在需要編程時切換到獨立編輯頁
- 系統需能將關卡結果回寫到遊戲進度

### FR-3 示範關

- 系統需支援示範關作為新積木解鎖節點
- 系統需支援玩家在示範關中以拖曳積木完成任務
- 系統需在驗證時直接顯示對應的 Python 轉換結果

### FR-4 支線練習關

- 系統需支援固定 5 題的支線練習關
- 題庫需固定，不採隨機抽題
- 練習關預設只能以 Python 作答

### FR-5 工具包

- 系統需提供工具包，用於存放已解鎖的 Blockly 積木
- 工具包中的可用積木需隨進度增加
- 玩家可在練習關卡住時開啟工具包改用積木輔助
- 工具包模式只能知道答案是否正確，不能直接作為通關結果
- 玩家若使用過工具包，仍需切回 Python 並以 Python 通過該題
- 工具包可在單題內不限次數開關
- 只要該題曾開啟過工具包，該題獎勵固定為 10%

### FR-6 電池能量

- 支線練習關開始時，電池能量歸零
- 未使用工具包時，單題獎勵 20%
- 使用工具包時，單題獎勵 10%
- 5 題結束後，電池能量需超過 80% 才能過關
- 超過 80% 的實作規則為只接受 90% 或 100%
- 若失敗，需等待 3 分鐘後重新挑戰整組練習關

### FR-7 驗證與評測

- 系統需驗證程式結構與輸出結果
- 系統需支援每個關卡各自的規則與測資
- 系統需區分示範關與支線練習關的驗證流程

### FR-8 進度與存檔

- 系統需保存主線、支線與程式關卡進度
- 系統需保存積木解鎖、工具包內容與劇情狀態
- 系統需保存支線練習關冷卻與完成狀態
- 系統需支援單機存檔

### FR-9 AI 助教

- 系統需保留 AI 助教
- AI 助教應以提示與引導為主
- AI 助教不應直接破壞 Python 練習要求

### FR-10 UI 與呈現

- 系統需以 2D 為主要方向
- 系統需支援節點式主地圖畫面
- 系統需支援角色貼圖與對話框互動
- 系統需支援劇情場景與編輯頁之間的切換

## 5. 非功能需求

- 目標平台為電腦單機
- 畫面切換與編輯頁切換需保持基本流暢
- 程式執行需維持隔離與可控
- 冷卻與支線進度狀態需可正確保存與恢復

- 美術風格與演出深度
