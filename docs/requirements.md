# 程式教育轉換系統 — MVP 需求文件

- 版本：1.1（草案）
- 更新日期：2026-03-02

## 1. 專案背景與目標

「本專案以 Demo 展示為主要目標，不以正式部署或軟體釋出為主要目標。」

### 1.1 背景

許多具備積木式程式設計基礎的學生，在轉換至文字型語言（如 Python）時，常因語法結構與表徵方式不同而產生困難。本專案旨在解決「積木 → Python」之間的思維轉換落差。

### 1.2 目標

本系統的核心目標為：

- 協助 13–16 歲具積木基礎之學生，理解積木與 Python 的對應關係
- 透過關卡式設計，引導學生完成雙階段驗證（積木 → Python）
- 培養學生將視覺結構轉換為語法結構的能力
- 以「任務／劇情」包裝學習流程，使學生提高投入度與持續學習意願

## 2. 教學內容範圍（Scope）

### 2.1 MVP 必含教學內容

- 輸入/輸出：`input`、`print`
- 變數與賦值
- 型別：整數（`int`）、布林（`bool`）
- 運算：`+` `-` `*` `/`
- 條件判斷：`if` / `else`
- 迴圈：`for`（以固定次數與 `range` 為主）

### 2.2 尚未決定項目（待評估）

- 區域變數 / 全域變數
- 巢狀結構（巢狀 `if` / `for`）

### 2.3 明確不包含項目（Out of Scope）

- 函式（`def`）
- `list` / `dict` / `tuple`
- `while`
- `import`
- 物件導向（`class`）
- 進階模組與外部套件

## 3. 使用者角色

### 3.1 學生（Student）

- 年齡 13–16 歲
- 具備積木基礎
- 主要任務：完成關卡並學會轉換思維

### 3.2 內容製作（Content Author）

- 編寫/維護教學內容與劇情/任務文本
- 設定關卡題目、測資與驗證規則
- Demo 階段內容可預先配置，不提供教師後台介面
- 須確保敘事內容與關卡學習目標一致

### 3.3 AI 助教（AI Tutor）

- 根據教案提供引導式提示
- 可讀取學生程式碼
- 不直接提供完整解答
- 僅使用當前關卡範圍內的概念

## 4. 系統學習流程

每一關卡流程如下：

1. （可選）劇情開場／任務目標說明
2. 閱讀教學內容
3. 完成積木任務
4. 積木驗證通過後解鎖 Python 任務
5. 完成 Python 任務
6. Python 驗證通過後（可選）劇情結尾／獎勵回饋，並解鎖下一關

關卡採順序解鎖制。

## 5. 系統功能需求（Functional Requirements）

### FR-1 關卡列表與解鎖機制

- 顯示關卡列表與解鎖狀態
- 未解鎖關卡不可挑戰
- 通過 Python 任務後解鎖下一關

### FR-2 教學頁（Learning Page，待設計）
- 提供進入關卡前/關卡中的教學內容呈現（形式待定）
- 教學方案（內容結構、呈現形式、是否分層、是否互動）待後續決定需求
- 教學內容需可與關卡學習目標、任務與提示策略對應
- 教學內容來源

### FR-3 劇情／任務入口（Story / Quest Entry）

- 作為「正式進入關卡」前的劇情/任務說明入口（Demo 可先以文字為主）
- 支援章節／任務結構：章節可包含多個關卡並以劇情串連
- 支援劇情節點：關卡前後與事件觸發（首次進入、連續失敗、通關等）
- 劇情進度需與關卡解鎖狀態一致，避免跳關造成斷裂

### FR-4 積木編輯區

- 引入現成積木環境
- 可拖曳與修改積木
- 可送出驗證
- 通過後解鎖 Python 任務

### FR-5 Python 編輯區

- 提供基本程式編輯功能
- 積木未通過前不可進入
- 驗證通過後解鎖下一關

### FR-6 趣味程式學習功能

- 支援至少一種「非純自由輸入」的互動模式（例如：拼圖）
- 互動模式需可與既有驗證系統共用測資／輸出驗證／超時限制
- 互動模式需可套用 AI 提示策略（提示不直接給完整解答）

### FR-7 送出與驗證系統

#### 驗證原則

- 以輸出型驗證為主
- 支援多組測資（動態測試）
- 所有測資通過才算成功

#### 輕量限制（部分關卡適用）

- 行數上限（排除空行與註解）
- 必須包含指定關鍵字（如 `for`）
- 禁止使用特定關鍵字
- 必須使用 `input`

#### 驗證需具備

- 輸出正規化（統一換行、去除尾端空白）
- 超時限制（避免無限迴圈）
- 基本錯誤回饋（顯示輸出差異或測資失敗資訊）



### FR-8 AI 助教互動（AI Tutor）

- 提供聊天式或提示式介面，根據當前關卡與內容進行引導
- 允許讀取學生程式碼，用於提示、診斷與錯誤引導
- 不直接提供完整解答；不引入超出當前關卡範圍的語法/概念
- AI 互動需可被限制在 Demo 可控範圍內（避免不可預期輸出）
  
#### AI 設計待定項（預留）
- 模型使用邊界：可讀取的上下文範圍、可回覆的內容邊界、拒答策略
- 與教案/關卡的橋接：教案資料格式、檢索/引用方式、提示策略如何對應學習目標
- 安全與風險控管：避免洩題、避免產生超出範圍解法、避免鼓勵不安全程式行為
- 可觀測性：最少需要記錄哪些互動（用於除錯/改進），Demo 階段可簡化

## 6. 非功能需求（NFR）

（具體數值待團隊決議）

- 執行環境需具備超時控制
- 驗證回應時間應維持在合理範圍（例如 2 秒內）
- 執行環境需具備基本安全隔離機制

## 7. 資料與狀態管理（MVP 初步設計）

- 關卡解鎖狀態需被保存
- （若有劇情）需保存章節／任務進度與已讀對話狀態

## 8. 待團隊決議事項

- Python 執行環境選型（前端 / 後端 / 現有引擎）
- 驗證超時秒數
- 是否支援帳號系統
- 是否納入巢狀與作用域概念
