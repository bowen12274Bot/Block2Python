# 劇情演出需求

- 文件版本：0.0
- 更新日期：2026-03-22
- 文件定位：核心功能需求子文件

本文件定義劇情演出場景的需求，屬於功能與呈現交界的實作需求。

建議先讀：

- `docs/requirements/product_context.md`
- `docs/requirements/gameplay_requirements.md`

再回到本文件閱讀劇情演出的細部條目。

## 1. 適用範圍

本文件聚焦在正式劇情演出場景的第一版骨架，不處理最終美術定稿、完整鏡頭語言、分支選項與高成本角色動畫系統。

此需求至少覆蓋以下使用情境：

1. 玩家完成建角後進入開場劇情。
2. 玩家從主地圖控制浮頁進入劇情節點。
3. 玩家完成劇情後返回流程主控並切往下一步。
4. 玩家在成功或失敗結果節點中觀看回饋型劇情。

## 2. 功能需求

### FR-SP-1 獨立劇情場景

- 系統需提供獨立劇情場景，不與主地圖畫面共用主要版面。
- 劇情場景需可由 flow coordinator 切入與切出。
- 劇情場景需可承接目前 scene mode 的資料流。

### FR-SP-2 背景呈現

- 場景需支援全畫面背景圖。
- 第一版至少需支援單張靜態背景。
- 若當前段落未指定新背景，系統需沿用上一段背景狀態。

### FR-SP-3 角色呈現

- 場景需至少支援左右兩個角色槽位。
- 角色需支援顯示、隱藏、亮起、變暗與剪影模式。
- 第一版可先不處理骨架動畫、嘴型同步與多角色複雜進退場。
- 若發話者存在於場景中，系統需能讓其成為當前視覺焦點。

### FR-SP-4 對話框

- 對話框需固定於畫面下方。
- 對話框需採半透明或等價的可讀性設計。
- 對話框需包含發話者名牌區與正文區。
- 若為旁白段落，系統需允許不高亮任何角色。

### FR-SP-5 劇情推進

- 系統需一次只顯示一段文字。
- 玩家點擊後需進入下一段。
- 播放到最後一段後，系統需發出完成事件，交回流程主控。
- 畫面需有可辨識的「可繼續」提示。

### FR-SP-6 視覺焦點規則

- 當前發話角色需預設為亮起狀態。
- 非當前發話角色需預設為變暗或剪影狀態。
- 若段落明確指定角色狀態，系統需以段落設定優先。

### FR-SP-7 內容擴充空間

- 劇情資料結構需保留背景切換、角色 pose、表情與視覺狀態欄位。
- 第一版即使不完全使用，也不能把資料模型鎖死在只有 `speaker` 與 `text`。
- 規格需保留未來加入打字機效果、音效與簡單進場動畫的空間。

## 3. 非功能需求

### NFR-SP-1 可讀性

- 白字或淺色字在對話框上的對比需足夠。
- 名牌與正文需有清楚層級，不可互相混淆。
- 在 16:9 常見解析度下，正文不可過度貼邊或過窄。

### NFR-SP-2 可維護性

- 畫面結構需明確分層，至少拆分背景、角色、對話框、提示等區域。
- 劇情 UI 腳本不可直接依賴 raw `GameState`，應吃整理過的 view model。
- 文件需與實作對齊，避免後續 scene schema 與 Godot UI 各自演化。

### NFR-SP-3 可替換性

- 第一版可使用 placeholder 美術資產。
- 不同角色圖、背景圖與對話內容需能在不重寫場景的前提下替換。

## 4. 第一版範圍

第一版應完成：

- 獨立劇情場景
- 單背景圖顯示
- 左右角色槽
- 角色亮起 / 變暗 / 隱藏 / 剪影
- 底部半透明對話框
- 名牌與正文
- 點擊逐段推進
- 劇情完成事件

第一版不包含：

- 分支選項
- Live2D、Spine 或等價角色系統
- 鏡頭移動
- 複雜特效
- 配音
- 多層互動 UI

## 5. 驗收準則

- 可從現有 flow 正常切入劇情場景。
- 畫面可顯示背景、左右角色與下方對話框。
- 玩家可透過點擊逐段讀完整段劇情。
- 當前發話者能以亮起或等價方式被辨識。
- 最後一段播完後，流程能回到既有 coordinator 控制。
