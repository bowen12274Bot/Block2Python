## 1. 功能需求

### FR-1 地圖與劇情

- 系統需提供節點式主地圖。
- 系統需提供明確主線路線。
- 目前主線需以 5 關版本為基準：`Input Gate`、`Variable Base`、`If Canyon`、`Loop Lab`、`Bug King Castle`。
- 系統需支援支線節點。
- 系統需支援地圖節點上的劇情事件與對話框互動。
- 系統需支援主地圖前後的劇情觸發點，以承接開場導入與後續故事背景交代。
- 系統需支援將起始世界觀與後段背景揭露分層處理，避免故事一開始就揭露 `Bug King` 的完整背景。

### FR-1A 開場進入流程

- 系統需提供進入頁，作為玩家首次進入遊戲的流程入口。
- 系統需允許玩家在進入頁選擇男 / 女角色外觀。
- 系統需允許玩家在進入頁輸入玩家名稱。
- 系統需在玩家角色建立成功後先進入開場劇情流程，再進入主地圖。
- 系統需保留進入頁前後的劇情觸發空間，開場劇情至少需有一段可承接建角完成後導入主地圖的流程骨架。

### FR-2 關卡進入與切換

- 系統需能從地圖節點進入控制浮頁。
- 系統需能由控制浮頁進入劇情事件、示範關與支線練習關。
- 系統需能在需要編程時切換到獨立編輯頁。
- 系統需能在劇情、控制浮頁、主地圖與關卡頁面之間維持一致切換流程。
- 系統需能將關卡結果回寫到遊戲進度。

### FR-2A 控制浮頁

- 系統需提供控制浮頁，作為地圖節點與後續內容之間的統一入口。
- 控制浮頁需能承接該節點可進入的劇情、示範關或支線練習關。
- 控制浮頁需避免玩家在劇情結束後回到不明確的中間流程狀態。
- 控制浮頁與劇情、示範關、支線練習關的進入規則，需可配合既有實作再細化。

### FR-3 示範關

- 系統需支援示範關作為新積木解鎖節點。
- 系統需支援玩家在示範關中以拖曳積木完成任務。
- 系統需在驗證時直接顯示對應的 Python 轉換結果。

### FR-4 支線練習關

- 練習關需要在示範關有進入過才能解鎖。
- 系統需支援固定 5 題的支線練習關。
- 題庫需固定，不採隨機抽題。
- 練習關預設只能以 Python 作答。

### FR-5 工具包

- 系統需提供工具包，用於存放已解鎖的 Blockly 積木。
- 工具包中的可用積木需隨進度增加。
- 玩家可在練習關卡住時開啟工具包改用積木輔助。
- 工具包模式只能知道答案是否正確，不能直接作為通關結果。
- 玩家若使用過工具包，仍需切回 Python 並以 Python 通過該題。
- 工具包可在單題內不限次數開關。
- 只要該題曾開啟過工具包，該題獎勵固定為 10%。

### FR-6 電池能量

- 支線練習關開始時，電池能量歸零。
- 未使用工具包時，單題獎勵 20%。
- 使用工具包時，單題獎勵 10%。
- 5 題結束後，電池能量需超過 80% 才能過關。
- 超過 80% 的實作規則為只接受 90% 或 100%。
- 若失敗，需等待 3 分鐘後重新挑戰整組練習關。

### FR-7 驗證與評測

- 系統需驗證程式結構與輸出結果。
- 系統需支援每個關卡各自的規則與測資。
- 系統需區分示範關與支線練習關的驗證流程。

### FR-8 進度與存檔

- 系統需保存主線、支線與程式關卡進度。
- 系統需保存積木解鎖、工具包內容與劇情狀態。
- 系統需保存支線練習關冷卻與完成狀態。
- 系統需保存玩家角色建立結果，至少包含角色選擇與玩家名稱。
- 系統需支援單機存檔。

### FR-9 AI 助教

- 系統需保留 AI 助教。
- AI 助教應以提示與引導為主。
- AI 助教不應直接破壞 Python 練習要求。

### FR-10 UI 與呈現

- 系統需以 2D 為主要方向。
- 系統需支援開場進入頁、節點式主地圖、控制浮頁、獨立劇情場景與編輯頁之間的切換。
- 系統需支援角色貼圖與對話框互動。
- 劇情演出場景需能承接對話式演出。
- 劇情演出的背景、角色狀態、對話框位置與逐段點擊規則，依 `docs/requirements/core/story_presentation_requirements.md` 定義。
