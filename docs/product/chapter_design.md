# 章節設計

## 1. 章節結構原則

- 遊戲正式流程應先有開場入口，再進入主地圖。
- 遊戲以節點式主地圖推進。
- 主地圖視覺方向暫以類似 Candy Crush 的節點式關卡地圖作為參考。
- 每個節點應先進入控制浮頁，再由控制浮頁導向劇情、示範關或支線練習關。
- 主線負責推進故事與教學能力建立。
- 支線練習關負責累積能量並驗證玩家 Python 作答能力。
- 目前主線已收斂為 5 關：前 4 關建立能力，第 5 關作為最終整合與故事收束。

## 2. 標準章節流程

1. 進入開場流程。
2. 在進入頁建立玩家角色。
3. 建角完成後先進入開場劇情或背景交代。
4. 開場劇情播放完成後進入節點式主地圖。
5. 點選節點後進入控制浮頁。
6. 由控制浮頁進入劇情、示範關或支線練習關。
7. 若進入劇情，劇情播放完成後返回流程主控。
8. 若進入示範關，解鎖新積木並建立積木與 Python 對應理解。
9. 若進入支線 5 題練習關，累積電池能量並檢查是否超過 80%。
10. 完成當前內容後回到主地圖並解鎖下一個主線節點。

## 3. 主線章節方向

目前主線章節已收斂為：

1. `Input Gate`
2. `Variable Base`
3. `If Canyon`
4. `Loop Lab`
5. `Bug King Castle`

章節定位如下：

- 前 4 關負責建立輸入、變數、條件判斷與迴圈四個核心能力。
- 第 5 關 `Bug King Castle` 不作為新語法教學關，而是前 4 關的整合應用關。
- `Bug King Castle` 同時是劇情收束關，負責承接 `Bug King` 真實背景與產品寓意的揭露。

## 4. 開場入口規劃

- 遊戲不應在正式版本中直接進入主地圖。
- 玩家應先進入一個進入頁，建立自己的遊戲角色。
- 進入頁目前至少需要包含：
  - 男 / 女角色選擇
  - 玩家名稱輸入
- 只有在玩家角色建立成功後，才可進入開場劇情流程。
- 開場劇情播放完成後，才進入主地圖主流程。
- 進入頁前後需保留劇情觸發點，用於交代玩家背景、Code Planet 狀況與後續冒險動機。
- 目前可先以 placeholder 劇情頁作為流程骨架，完整腳本、呈現方式與觸發時機後續再補。

## 5. 關卡角色分工

### 劇情

- 目的：承接節點脈絡、交代任務情境與推進故事。
- 推進方式：以對話式演出為主。
- 發話者：可包含劇情角色、旁白與其他角色。
- 位置：作為控制浮頁之後可進入的一種內容。
- 演出場景：獨立劇情場景，包含空背景、角色剪影與下方半透明對話框。
- 互動方式：一次顯示一段文字，玩家點擊後進入下一段，直到整段劇情播放完成。
- 視覺演出：角色剪影需支援亮起、變暗、出現與消失。
- 世界觀揭露需分層進行：故事起點先交代 Code Planet 失控與修復任務，`Bug King` 的真實背景屬於後段劇情才逐步揭露的內容。

### 控制浮頁

- 目的：作為地圖節點與後續內容之間的統一入口。
- 功能：承接劇情、示範關與支線練習關的進入控制。
- 理由：避免玩家在劇情結束後回到不明確的中間流程狀態。
- 實際入口規則仍需依既有實作再細化。

### 示範關

- 目的：教學與新積木解鎖。
- 表現：積木拖曳 + 驗證時顯示 Python 轉換結果。

### 支線練習關

- 解鎖：需要進入過示範關。
- 目的：練習 Python 作答。
- 結構：固定 5 題。
- 題庫：固定題庫。
- 限制：預設只能以 Python 通關。

### 工具包

- 目的：防卡住。
- 用法：可在單題中不限次數開關。
- 限制：只要曾開啟過工具包，該題能量固定為 10%。

### 電池

- 起始值：0%。
- 單題標準獎勵：20%。
- 工具包題目獎勵：10%。
- 通關門檻：整組 5 題後必須超過 80%（即 90% 或 100%）。
- 失敗懲罰：整組練習關冷卻 3 分鐘。

## 6. 章節規劃待補

- 各章示範關內容與練習題內容。
- 各章對應的程式概念。
- 章節難度曲線。
- 開場劇情腳本與進入頁前後的觸發時機。
- 控制浮頁上的劇情、Demo、練習關入口規則。
- 劇情角色、旁白與其他角色的出場原則。
- `Bug King Castle` 的最終對決設計與背景揭露節奏。
- 劇情場景的實際腳本節奏與鏡頭安排。
