# 遊戲第一個 Vertical Slice 計畫

- 文件版本：0.1
- 更新日期：2026-03-14
- 文件定位：定義第一個可玩遊戲切片的範圍、驗證目標、流程與交付標準

## 1. 目的

本文件用於定義第一個最小可玩 vertical slice，讓團隊以最小範圍驗證「遊戲主流程 + 程式挑戰流程 + 狀態回寫」是否成立。

本文件不追求完整章節內容，也不處理最終美術與完整劇情；重點是建立一條能實際操作、能驗證轉型方向的可玩流程。

## 2. 本切片要回答的問題

- 節點式主地圖、劇情節點與程式關卡能否順暢切換
- 示範關與支線練習關是否能形成可理解的學習節奏
- 工具包、電池能量與整組 5 題規則是否可被玩家理解
- 關卡結果能否正確回寫到遊戲進度並解鎖下一節點

## 3. 切片範圍

### 3.1 必含流程

1. 進入節點式主地圖
2. 選擇一個可進入的主線節點
3. 播放一段劇情 / 任務說明
4. 進入一個示範關
5. 完成後切入一組固定 5 題的支線練習關
6. 練習關結束後進行電池能量結算
7. 根據結果回寫存檔並解鎖下一個節點

### 3.2 本切片至少包含的內容

- 一張最小節點式主地圖
- 一個主線入口節點
- 一段最小劇情文本
- 一個示範關
- 一組固定 5 題的支線練習關
- 一次完整的電池能量結算
- 一次節點解鎖回饋

### 3.3 本切片暫不包含

- 多章節地圖
- 複雜分支劇情
- 多城市完整內容
- 長篇過場演出
- 最終版美術與音效
- 線上功能

## 4. 流程定義

### 4.1 主地圖階段

- 玩家看到節點式主地圖
- 系統清楚標示目前可進入的節點
- 玩家可從主線節點進入劇情 / 任務流程

### 4.2 劇情階段

- 以對話框或等價簡化形式呈現
- 劇情需清楚說明當前任務與進入程式關卡的理由
- 劇情結束後切到示範關

### 4.3 示範關階段

- 目的是讓玩家理解新積木與 Python 對應關係
- 以積木拖曳為主
- 驗證時直接顯示對應 Python 結果
- 示範關完成後，解鎖支線練習關

### 4.4 支線練習關階段

- 固定 5 題
- 預設以 Python 作答
- 玩家在單題中可開啟工具包獲得積木輔助
- 若曾開啟工具包，該題獎勵固定為 10%

### 4.5 結算與解鎖階段

- 每題完成後更新當前能量
- 5 題結束後檢查總能量是否為 90% 或 100%
- 若成功，解鎖下一個節點
- 若失敗，寫入冷卻時間並要求重跑整組練習關

## 4.6 第一版切片內容實例

本節用於把切片流程壓成可實作的最小內容樣板。名稱可後續微調，但流程角色先固定。

### 節點清單

1. `map-entry`
   - 類型：入口節點
   - 功能：讓玩家進入第一個主線任務

2. `story-intro`
   - 類型：劇情節點
   - 功能：說明城市失控與當前修復任務

3. `demo-basic-io`
   - 類型：示範關節點
   - 功能：透過積木建立 input / output 與 Python 對應

4. `practice-basic-io`
   - 類型：支線練習關節點
   - 功能：進入固定 5 題的 Python 練習組

5. `result-basic-io`
   - 類型：結果節點
   - 功能：顯示電池結算結果與是否解鎖下一節點

6. `next-main-node`
   - 類型：下一個主線節點
   - 功能：作為本切片驗證成功後的解鎖目標

### 劇情段落清單

- `scene-city-alarm`
  - 內容：Byte 告知玩家第一個城市的基礎輸入輸出模組失控
  - 任務：先透過示範關理解積木與 Python 的對應，再進入修復練習

- `scene-practice-unlock`
  - 內容：示範關完成後，Byte 說明接下來要用 Python 完成一組修復任務
  - 任務：進入固定 5 題練習關，累積電池能量

- `scene-result-success`
  - 內容：城市局部恢復供能，下一個節點解鎖

- `scene-result-fail`
  - 內容：修復失敗，系統需冷卻後重新挑戰

### 示範關清單

- `demo-basic-io-01`
  - 教學目標：理解 `input` / `print`
  - 形式：積木拖曳
  - 成功條件：能生成對應的 Python 輸入輸出程式

### 支線 5 題清單

1. `practice-basic-io-01`
   - 讀入一個整數並原樣輸出

2. `practice-basic-io-02`
   - 讀入兩個整數並輸出總和

3. `practice-basic-io-03`
   - 讀入名字並輸出問候語

4. `practice-basic-io-04`
   - 讀入一個整數並輸出其兩倍

5. `practice-basic-io-05`
   - 讀入兩個整數並輸出較大的值

以上題目先作為內容骨架；正式題面與測資後續再細化。

## 4.7 狀態轉移

### 成功路徑

`map-entry` -> `story-intro` -> `demo-basic-io` -> `practice-basic-io` -> `result-basic-io(success)` -> `next-main-node`

### 失敗路徑

`map-entry` -> `story-intro` -> `demo-basic-io` -> `practice-basic-io` -> `result-basic-io(fail)` -> `practice-basic-io`

### 失敗回圈規則

- 練習關整組未達通關門檻時，不退回示範關
- 失敗後停留在結果節點
- 冷卻結束後，重新進入同一組 5 題練習關

## 4.8 切片內容對應表

- 劇情入口：`scene-city-alarm`
- 示範關：`demo-basic-io-01`
- 練習關群組：`practice-basic-io`
- 成功結果段落：`scene-result-success`
- 失敗結果段落：`scene-result-fail`
- 解鎖目標：`next-main-node`

## 5. 驗證標準

### 5.1 功能驗證

- 地圖可進入節點
- 劇情可正確切入示範關
- 示範關可正確完成並切入支線練習關
- 支線 5 題流程可完整跑完
- 電池能量計算與工具包規則正確
- 結果可正確回寫並影響節點狀態

### 5.2 體驗驗證

- 玩家能理解當前自己在哪個流程階段
- 玩家能理解為什麼要先示範關、再練習關
- 玩家能理解工具包有代價，且不能直接用來通關
- 玩家能理解成功 / 失敗後下一步會發生什麼

## 6. 切片完成定義

- 團隊可完整演示一次從主地圖到節點解鎖的流程
- 演示過程中不需要人工補敘述來解釋系統狀態
- 成功與失敗兩種流程都能正確回寫
- 本切片可作為後續擴展章節與內容的基準模板
