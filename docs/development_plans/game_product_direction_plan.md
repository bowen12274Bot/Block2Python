# 產品遊戲化計畫

- 文件版本：0.1
- 更新日期：2026-03-14
- 狀態：已納入第二輪方向決策
- 文件定位：產品方向轉向文件，負責定義 game-first 的目標、範圍、里程碑與未決產品問題；不負責細部技術架構設計。

## 1. 目標

- 將專案從 demo-first 重新定位為 game-first。
- 在實驗性開發階段做出小規模但可玩的遊戲階段。
- 保留真正有槓桿價值的程式挑戰技術核心。
- 讓程式關卡成為主線推進的必要步驟，而不是外掛功能。

## 2. 方向收斂工作流

### 2.1 產品與敘事

- 定義遊戲主 premise
- 定義主線與支線結構
- 定義玩家推進節點與關卡節奏
- 定義劇情節點如何切入編輯頁與返回遊戲流程

### 2.2 產品對架構的前提

- 確認哪些體驗屬於遊戲主體，哪些屬於程式挑戰子系統
- 確認遊戲流程需要回寫哪些狀態到存檔 / 進度模型
- 確認工具包、積木解鎖與電池能量規則的產品目標
- 將技術承接方式交由 `game_architecture_transition_plan.md` 落地

### 2.3 UX / 呈現

- 定義 2D 呈現方向
- 定義角色貼圖 + 對話框互動方式
- 定義劇情演出與程式 UI 的切換體驗
- 定義示範關中積木轉 Python 的即時展示方式

### 2.4 內容製作流程

- 定義主線 / 支線內容製作流程
- 定義程式關卡製作流程
- 定義劇情節點與程式關卡的對應流程
- 定義示範關、支線練習關與獎勵規則的製作格式

## 3. 里程碑

### M1. 方向定稿

- 產品方向確認
- 遊戲類型與平台確認
- 程式關卡在主流程中的定位確認
- 主線示範關 / 支線練習關結構確認

### M2. 架構定稿

- 遊戲端與程式挑戰端的責任邊界確認
- 存檔 / 進度需要承接的產品狀態確認
- 工具包與電池能量系統的產品規則確認
- 供技術轉型文件採納的前提條件確認

### M3. 小規模遊戲階段

- 一段完整主線流程可玩
- 一段程式挑戰流程可玩
- 一段劇情 + 關卡 + 存檔流程可驗證
